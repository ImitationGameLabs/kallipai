# Message catalogs (i18n)

UI copy lives in per-domain message catalogs under
`packages/kallip-ui/i18n/project.inlang/messages/{en,zh}/<domain>.json`,
compiled by paraglide (`deno task i18n`) into typed functions in
`src/paraglide/` (generated, gitignored). Consumers import from
`../paraglide/messages.js` and call keys as functions: `key()`, or
`key({ placeholder })` — placeholders are required TS parameters.

## Key naming

A key is `<prefix>_<stem>[_<role>]`, snake_case, and follows a two-layer prefix
rule:

- **Domain prefix** for cross-surface copy: `common_`, `error_`, `remaining_`,
  `agent_state_`, `shell_`, `shell_status_`, `connection_`, `auth_`, `signal_`,
  `timeline_`, … A string rendered on more than one page gets a domain prefix,
  never a page prefix.
- **Page prefix** for page-owned copy: `nav_`, `login_`, `oauth_`, `register_`,
  `pair_`, `connect_`, `chat_`, `settings_`, `user_`, `tagma_`/`tagmata_`
  (entity page vs list page), `room_`/`rooms_`/ `roomsettings_`, and the manage
  pages `manage_overview_`, `manage_agent_`, `manage_agents_`, `manage_budget_`,
  `manage_profiles_`, `manage_schedules_`. The bare `manage_` prefix is reserved
  for manage-section layout state shared across those pages. The guard also
pins which file each prefix lives in (`PREFIX_FILES`); several prefixes
share a file (`agent_state_` in common.json, `connection_`/`nav_` in
shell.json).

The prefix vocabulary is **closed**: adding a new prefix means adding it to
`PREFIXES` in the guard test (and here) — an unknown prefix fails
`src/i18n_catalog_test.ts`.

Role suffixes name what a string is (`_title`, `_heading`, `_label`, `_hint`,
`_placeholder`, `_desc`, `_aria`, `_link`, `_action`, …). Keys whose stem
already ends in a data word (`_consumed`, `_remaining`) simply have no role
suffix. Ambiguous abbreviations (`_err`, `_btn`, `_txt`, `_msg`, `_caption`)
are banned anywhere in a key; error copy uses the `error_` domain prefix or
an `_error`/`_failed` role suffix.

Plurals come in `_one`/`_other` pairs selected at the call site; a lone `_one`
or `_other` fails the guard. The legacy key `register_have_account` (formerly
`register_have_one`) predates this — "one" there is a pronoun, not a plural
marker.

## Same-value keys

Two keys with identical English values are allowed only as deliberate synonyms
(nav labels that may drift from page headings on purpose). Every such group is
pinned in `SYNONYMS` in the guard test; a new same-value group fails the suite
until it is either de-duplicated or listed with a reason.

The synonym check runs against the **en** catalog only; zh translations
collide far more often and those collisions are accepted as translation
coincidence, not guarded.

## Guard

`packages/kallip-ui/src/i18n_catalog_test.ts` enforces, on every test run: en/zh
key and placeholder parity, no duplicate key across files, the closed prefix
vocabulary, banned role abbreviations, `_one`/`_other` pair integrity, the
synonym allowlist (en), prefix-to-file attribution, and that
settings.json's pathPattern matches the
guard's file list. Compile-time safety (the generated `.d.ts` make unknown keys
and missing placeholders type errors) plus this guard replaces runtime
missing-key fallbacks.

## Workflow

A note on paths: `settings.json`'s `pathPattern` entries resolve relative to
the inlang project root (`packages/kallip-ui/i18n/`, the parent of
`project.inlang/`) — hence the `./project.inlang/messages/…` prefix — while
`deno task i18n` must run from the repo root.

1. Add the key to the right domain file in **both** `en/` and `zh/`.
2. `deno task i18n` regenerates `src/paraglide/`.
3. Reference the generated function;
   `deno task --filter @kallipai/kallip-ui check` verifies types.
4. `deno test` (in `packages/kallip-ui`) runs the catalog guard with the rest of
   the suite.

zh conventions: full-width punctuation, curly quotes `“”`, spaces around
Latin/digit runs, tagma/tagmata render as 智能体编队 (no plural split),
`agora`/`lesche` stay untranslated, agent renders as 智能体, room/rooms
render as 群聊, token
counts use the singular "token".
