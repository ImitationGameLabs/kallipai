## 升级会跑迁移

本节每种形态都是原位升级，拥有存储的那些服务在启动时自己把存储迁到新形状：装上新版本、重启服务，模式就跟上了，没有单独一步要人去跑迁移命令。

有一件要先计划的。在 PostgreSQL 上，迁移器把一次启动待跑的那批迁移放进同一个事务，批里的建索引就一直持有那张表的写锁，直到整批提交。`CREATE INDEX CONCURRENTLY` 本可以不加锁地建，但它不能在事务块里跑，这一批也就用不上。忙起来的部署该在升级前掂量的是讨论那一条索引，它建在 `room_messages` 上：发过的每条消息都在这张表里。

发布说明里点到建索引时，先看你这张表有多少。表大的部署把这次启动放进一段清静时间：停服务、再起，让启动去做构建。提交成功的那批只跑一次；整批失败则什么都没记下，下次启动整批重跑，同一批里的多个建索引共用这一段窗口。
