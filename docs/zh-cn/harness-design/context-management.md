KallipAI 的上下文管理是显式的：agent 经工具掌控自己的注意力。

## 设计哲学

一般的上下文压缩做法有两种：`/compact` 命令手动压缩，以及 auto-compaction：一个简单的阈值机制，上下文到达阈值后由智能体运行框架（agent harness）触发一次压缩。

KallipAI 实现的是 agentic 上下文管理：通过 `pin`、`unpin`、`evict` 这组上下文原语，由 agent 自己管理自己的注意力，即决定什么应该留在上下文中。这在某种程度上与人的注意力管理相似：人在做一件事时，知道自己应该对哪些内容保持持续注意，直到脱离这件事。

/compact 式的手动压缩仍然可用：告诉 agent“你现在需要压缩上下文了”，agent 基本不会拒绝这个提醒，随即主动触发压缩过程。

这个机制的一个好处是时机：agent 自己知道什么时候适合压缩，比如一个任务结束、下一个任务开始前的间隙；而阈值触发的 auto-compaction 经常落在一个任务执行的中间。阈值触发的压缩应当是兜底保护机制，而不是常规手段。

### 上下文分层

上下文存储持有两层，按优先级组合：

| 层           | 内容           | 行为                                       |
| ------------ | -------------- | ------------------------------------------ |
| 固定层       | 带标签的条目   | 始终包含。在驱逐中存活。                   |
| 工作轮次     | 按时间的消息   | 受驱逐与压缩管辖（最新的在最后）。         |

每轮是一个 `Vec<Message>`（assistant 消息 + 工具结果），带预缓存的 Token 估算。

超大的外部消息在进入工作轮次处做尺寸守卫：超过入口上限即被切成头尾切片，加一条指向溢出原件的横幅；请求期压缩（预算超限时以摘要替换旧轮次）仍是预算管理层。两道守卫叠加，互不替代。

### 四个上下文工具

| 工具             | 作用                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------- |
| `context_pin`    | 把带标签的条目加进固定层。固定条目在驱逐与压缩中存活。                                     |
| `context_unpin`  | 从固定层移除条目。此后其内容可被驱逐。                                                     |
| `context_evict`  | 保留最新的若干轮次，把更早的轮次压缩成一条作为 `context_summary` 固定的摘要。               |
| `context_status` | 返回快照：固定条目及其 Token 数、轮数、轮 Token。                                               |

### `/compact` 作为特例

多数 coding agent 里的 `/compact` 命令直接映射到 `context_evict`：agent 写一份保住关键事实的摘要，工具原子地固定摘要并驱逐保留窗口之外的轮次。窗口本身由配置决定、不是工具参数（轮数上限加有效预算的份额），agent 无法从一次调用里放宽它；Token 份额与固定预算一样由活跃窗口推导，profile 换窗口则随之移动；轮数上限是配置数字，不随窗口变化。配置指 tagma 级默认值，外加 spawn 请求可为该 agent 携带的两个字段（`context_keep_turns`、`context_keep_tokens_ratio`）：supervisor 能单独收紧某个子 agent 的窗口，而不改动其余 agent 的默认。由 agent 决定保留什么：压缩不是隐藏的启发式，而是显式的 agent 动作。

每次驱逐都替换上一份 `context_summary`：永远只有一份摘要，因此新文本必须接住旧文本里的事实。驱逐是保留规则而不是预算保证——最新窗口留下来是因为它最新，不是因为它在警告阈值之下，所以驱逐之后上下文仍可能高于某个阈值。

摘要会写明覆盖范围，而这一行只由手动驱逐写入：工具从上下文存储算出它、给它打上自己的标记，自动压缩在继续转述之前会把它剥掉——范围行说的只是某一刻的存储状态，不是长期事实。该行点名边界轮次并数出存留轮数，而不写区间——固定条目与对话轮共用同一编号计数器，写出区间等于声称存在实际不存在的轮次。回复会报告本次生效的窗口：轮数上限配成 0 时全部压缩并以 note 说明，而最新一轮本身就超出 Token 份额时以 degraded 报告。
