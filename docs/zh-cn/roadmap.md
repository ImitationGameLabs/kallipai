## P1 - 生产级本地 agent 团队

目标：一个满足编码等基本 agent 需求的本地 agent 团队，建立在 agentic 设计之上。

- **Agentic 的 agent 管理**：agent 拉起并管理其他 agent；团队自组织，而非由人类 operator 自上而下驱动
- **非阻塞权限控制**：有风险的动作走异步审批（延迟执行），审批在别处进行时 agent 继续工作
- **agent 间通信**：agent 之间的异步消息
- **自管理的 agentic 上下文**：每个 agent 掌控自己的上下文（pin / evict），而非被系统悄悄摘要
- **随团队演化的 skill 系统**：skills 从团队经验中积累并与之共同演化，团队内共享
- **抗误用的工具集**：工具的形状让 agent 难以误用
- **生产强化**：可靠性、持久化、可观测性、成本/用量追踪、测试覆盖

## P2 - 可扩展、可远程管理的 agent 团队

目标：能快速部署与扩展的 agent 团队，随时随地经移动端与云管理。

- **部署与扩展**：快速拉起并横向扩展 agent 团队
- **移动应用**：在移动设备上管理 agent 团队
- **云控制**：把移动客户端桥接到跨实例的团队

## P3 - Agent 公司

目标：一家零员工的公司，完全由 agent 运营，以一个实体服务自己的客户并承接工作。

- **多团队组成**：公司由多个协作团队（P2 的可部署单元）构成
- **面向客户**：有自己的客户，承接任务与项目，交付成果
- **完全自主**：端到端由 agent 运营，没有人类员工；人类是客户，不是职员
- **组织记忆**：角色、层级与知识作为公司的记忆存续，超越任何单个 agent

### 技术考量

- **沙箱广度**：动态 FS 限定与逐目录写互斥核心（一把读/写锁：同一时刻只有一个 agent 可持有对某目录的写访问，为多 agent 并发保安全）已落地，在 Linux 上经 landlock 对每个被 spawn 的 shell 强制执行。仍开放的隔离轴：cgroup 资源限制、网络出口控制、overlayfs 写时复制暂存，以及一个密钥代理工具。
- **harness 精进的工具调用度量**：工具调用结果（命令退出码与其暗示的误用、成功率、失败形态）是反馈信号，不是模型排名：模型固定时，它们显示我们的哪些工具与 CLI 设计把 agent 引向误用，指导持续精进以压低误用率。
